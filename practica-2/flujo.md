# GitFlow y Trunk-Based Development

GitFlow y trunk-based son dos formas de organizar el trabajo con ramas en Git.

GitFlow utiliza varias ramas para separar el desarrollo, las nuevas funciones y las correcciones.

Esto permite llevar un mayor control de los cambios antes de incorporarlos a la versión principal.

Sin embargo, también puede complicar el trabajo cuando hay muchas ramas abiertas.

Por otro lado, trunk-based busca que los desarrolladores integren sus cambios constantemente en una rama principal.

Las ramas que se utilizan suelen durar poco tiempo para evitar que se acumulen diferencias.

Este enfoque puede facilitar la colaboración y reducir los problemas al combinar código.

Aunque también requiere realizar pruebas frecuentes para evitar introducir errores.

Para una aplicación web, personalmente utilizaría trunk-based.

Considero que permite trabajar de una manera más ágil y mantener el proyecto actualizado.

Además, resulta conveniente cuando se realizan cambios pequeños y frecuentes.

De esta forma, el equipo puede integrar mejoras sin mantener demasiadas ramas al mismo tiempo.
